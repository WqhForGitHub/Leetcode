下面用**具体字符**，把 UTF‑8 / UTF‑16 / UTF‑32 的编码结果直接列出来，方便对照理解。

---

## 示例字符一览

| 字符 | 说明           | Unicode 码点 |
| ---- | -------------- | ------------ |
| A    | ASCII 英文字母 | U+0041       |
| 中   | 常用汉字       | U+4E2D       |
| 😀   | Emoji（笑脸）  | U+1F600      |

下面分别看它们在三种 UTF 编码下的**十六进制表示**。

---

## 1️⃣ 字符：`A`（U+0041）

### UTF‑8（1 字节）

```
41
```

### UTF‑16BE（大端，2 字节）

```
00 41
```

### UTF‑32BE（大端，4 字节）

```
00 00 00 41
```

📌 **特点**：  
ASCII 字符在 UTF‑8 中最省空间，UTF‑32 则“浪费”最多。

---

## 2️⃣ 字符：`中`（U+4E2D）

### UTF‑8（3 字节）

```
E4 B8 AD
```

### UTF‑16BE（2 字节）

```
4E 2D
```

### UTF‑32BE（4 字节）

```
00 00 4E 2D
```

📌 **特点**：

- UTF‑8 需要 3 字节（因为大于 U+07FF）
- UTF‑16 刚好 2 字节
- UTF‑32 仍然固定 4 字节

---

## 3️⃣ 字符：`😀`（U+1F600）

### UTF‑8（4 字节）

```
F0 9F 98 80
```

### UTF‑16BE（4 字节，代理对）

```
D8 3D DE 00
```

### UTF‑32BE（4 字节）

```
00 01 F6 00
```

📌 **关键点**：

- Emoji 属于 **辅助平面（> U+FFFF）**
- UTF‑16 必须用 **代理对（surrogate pair）**
- UTF‑32 直接存完整码点，最直观

---

## 4️⃣ 加上 BOM（字节序标记）的情况

| 编码     | 带 BOM 的文件开头 |
| -------- | ----------------- |
| UTF‑8    | `EF BB BF`        |
| UTF‑16LE | `FF FE`           |
| UTF‑16BE | `FE FF`           |
| UTF‑32LE | `FF FE 00 00`     |
| UTF‑32BE | `00 00 FE FF`     |

> ⚠️ UTF‑8 的 BOM 不是必须的，但在 Windows 环境中很常见。

---

## 5️⃣ 三种编码直观对比（以“中”为例）

| 编码   | 字节数 | 十六进制    |
| ------ | ------ | ----------- |
| UTF‑8  | 3      | E4 B8 AD    |
| UTF‑16 | 2      | 4E 2D       |
| UTF‑32 | 4      | 00 00 4E 2D |

---

## 一句话总结

- **UTF‑8**：变长（1–4 字节），网络/文件存储首选 ✅
- **UTF‑16**：变长（2 或 4 字节），Java / Windows / JavaScript 内部常用
- **UTF‑32**：定长（4 字节），简单但占空间，多用于底层处理

好，这次我们不只看结果，而是**一步一步推导**：给定一个 Unicode 码点，它是如何被“翻译”成 UTF‑8 / UTF‑16 / UTF‑32 的二进制形式的。

我会用同一个字符 **`中`（U+4E2D）** 作为主线，最后再用 **`😀`（U+1F600）** 补一刀关键难点。

---

## 一、先统一基础概念

### 1️⃣ Unicode 码点（Code Point）

- `中` → **U+4E2D**
- 转成二进制：

```
0100 1110 0010 1101
```

一共 **16 个有效位**

---

## 二、UTF‑32：最简单，直接存

### 规则

- **固定 4 字节**
- 高位补 0
- 不做任何变换

### 编码过程

```
U+4E2D
→ 00000000 00000000 01001110 00101101
→ 00 00 4E 2D （UTF-32BE）
```

✅ **特点**：

> 码点 = 编码值，几乎零学习成本

---

## 三、UTF‑16：2 字节 or 4 字节

### 1️⃣ 判断用几个字节

规则：

- U+0000 ~ U+FFFF → **2 字节**
- U+10000 ~ U+10FFFF → **4 字节（代理对）**

`U+4E2D` 在 BMP（基本多文种平面），所以用 **2 字节**

### 2️⃣ 编码过程

直接拆成两个字节：

```
0100 1110 0010 1101
→ 4E 2D
```

✅ **UTF‑16BE：**

```
4E 2D
```

✅ **UTF‑16LE（小端）：**

```
2D 4E
```

---

## 四、UTF‑8：变长编码（重点）

UTF‑8 的核心思想是：

> **用前缀位告诉解码器：“我这个字符占几个字节”**

### UTF‑8 编码模板

| 字节数 | 码点位数 | UTF‑8 二进制模板                      |
| ------ | -------- | ------------------------------------- |
| 1      | 7        | `0xxxxxxx`                            |
| 2      | 11       | `110xxxxx 10xxxxxx`                   |
| 3      | 16       | `1110xxxx 10xxxxxx 10xxxxxx`          |
| 4      | 21       | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` |

---

### 对 `中`（U+4E2D）编码

#### Step 1：确定字节数

- U+4E2D > U+07FF → **3 字节**

#### Step 2：写出二进制

```
0100 1110 0010 1101
```

#### Step 3：按模板填位

模板：

```
1110xxxx 10xxxxxx 10xxxxxx
```

填入：

```
1110 0100
10 111000
10 101101
```

#### Step 4：转十六进制

```
E4 B8 AD
```

✅ **这就是 UTF‑8 下的“中”**

---

## 五、关键难点：UTF‑16 的「代理对」（以 😀 为例）

`😀` → **U+1F600**

### Step 1：发现它不在 BMP

- U+1F600 > U+FFFF
- 必须用 **代理对（Surrogate Pair）**

### Step 2：减去 0x10000

```
0x1F600 - 0x10000 = 0xF600
```

### Step 3：写成 20 位二进制

```
0000 1111 0110 0000 0000
```

拆成高 10 位 / 低 10 位：

- 高 10 位：`0000111101` → `0x03D`
- 低 10 位：`1000000000` → `0x200`

### Step 4：加上代理区偏移

- 高位代理：0xD800 + 0x003D = **0xD83D**
- 低位代理：0xDC00 + 0x0200 = **0xDE00**

### Step 5：得到 UTF‑16 编码

```
D8 3D DE 00
```

✅ **这就是为什么一个 Emoji 在 UTF‑16 里会变成 4 个字节**

---

## 六、三种编码对比（核心逻辑）

| 编码   | 核心思想                          |
| ------ | --------------------------------- |
| UTF‑32 | 直接存，不压缩                    |
| UTF‑16 | 常用字符 2 字节，生僻字符用代理对 |
| UTF‑8  | 前缀标记长度，向后兼容 ASCII      |

---

## 七、一句话总结

> **UTF‑32 是“懒人版”，UTF‑16 是“折中版”，UTF‑8 是“工程版”。**
